Dashboard-wide initiative board

One board. One lane per initiative. One card per workstream.

The existing Initiatives overview becomes a seven-column kanban. A workstream card exists before a PR, keeps its identity as work advances, and gains PR links and review state without spawning a duplicate PR card.

Approved direction, frozen

This is an overview redesign, not a drill-in redesign.

The route is /initiatives. The global columns are Planned, Active, Verifying, Your Review, External Review, Blocked, and Done. Each initiative is one horizontal swimlane with sticky parent identity. At narrow widths, each initiative becomes its own stacked section in the same column order.

Non-negotiable identity rule
  • Cards represent workstreams, never PRs.
  • Opening a PR enriches the existing card.
  • No title, order, branch, or repo inference.
  • No child workstream means exactly one initiative fallback card.

02 · What is a card?

A persistent workstream identity.

Source and key

An explicit card is a direct child of the initiative root epic from the project Beads database. Its stable key is the child Bead id. Descendants contribute compact progress but do not become duplicate cards. With no direct child, synthesize one fallback keyed by the initiative id.

PR attachment

ateam pr add INIT PR --workstream BEAD records a canonical URL → Bead-id relation. The same card then shows one or more linked PRs and uses their gates to advance. Omitted mappings stay backward compatible and visibly unassigned.

Lifecycle

Bead status creates the card in Planned or Active. An attached open PR with no explicit gate, or an in-progress track:test workstream, is Verifying. Per-PR gates move that same card to Your Review, External Review, or Blocked. Closing the Bead moves it to Done.

03 · Total placement function

Every workstream appears once.

PrecedenceColumnRule for one persistent card

3Your ReviewAny attached PR has gate review and no higher-precedence blocker exists.
4VerifyingAn attached PR has empty/unknown gate, or the in-progress workstream has exact label track:test. Unknown gate is shown verbatim, never inferred as review.
5External ReviewAt least one PR is attached and every attached PR is external; no question/review/ungated PR remains.
6ActiveWorkstream status is in_progress.
7PlannedOpen/deferred/unknown nonterminal status. Preserve and display the raw status.
04 · Durable association contract

One sanctioned write, one structured read.

WRITEateam pr add <initiative> <url> --workstream <bead-id>. The option is backward compatible. Canonicalize the URL, keep existing PR seeding/idempotency, and validate the Bead against the initiative's project epic descendants when repo + epic are available.
STOREAppend repeatable pr-workstream: <canonical-url> <bead-id> lines to the initiative description. Exactly one ASCII space separates the two whitespace-free tokens. Re-adding the same pair is a no-op; one PR may map to one workstream, and conflicting remap is rejected.
READinternal/initiative parses the rail once. ateam list-json adds a sibling pr_workstreams array of {pr, workstream}, while existing prs, pr_reviews, and fields remain backward compatible.
JOINThe dashboard exact-joins canonical PR URL to review gate and exact-joins workstream id to the direct-child card. Invalid/stale mappings and legacy unmapped PRs are exposed as unassigned diagnostics; they never guess a card.
05 · Overview data path

Batch by repository, then project once.

Existing producer

The 15-second snapshot already runs open and closed ateam list-json, parses prs/pr_reviews, and builds InitiativeNode[]. Extend that same wire with pr_workstreams; do not add a per-card endpoint.

Controlled Beads reads

Group parsed initiatives by distinct non-empty repo. Run one bd -C REPO list --status=all --json per distinct repo through a small fixed-concurrency pool, never one process per initiative. Reuse per-repo last-known-good data on transient failure and prevent overlapping snapshot ticks.

Snapshot projection

For each initiative, select descendants of its epic (with initiative-label fallback for legacy data), derive direct-child workstreams and progress, and attach them to its InitiativeNode. The existing SSE snapshot therefore supplies the entire board and keeps it live without drill-in fetches.
