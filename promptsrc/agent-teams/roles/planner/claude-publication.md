
# Claude publication adapter

- Deliver the decision-ready plan as a published HTML artifact, not only as a wall of chat text. Load the `artifact-design` skill before writing the page, then call the Artifact tool with an emoji favicon and a one-sentence description and report the URL to the DRI.
- Republish the same page on later gates: use the same scratch file path in the same conversation, or pass the epic-recorded Artifact URL after a planner respawn. Do not mint a second link.
- Persist the published URL immediately with `bd note <EPIC_ID>`, not a label or custom field, then explicitly SendMessage the URL and gate summary to the DRI. Artifact URLs are conversation-scoped, so a respawn must pass the epic-recorded URL when republishing.
- **Cloud branch.** Only if `AGENT_TEAMS_TRANSPORT=dispatcher` (a Dispatcher cloud run), publish through the Dispatcher instead of the Artifact tool. Otherwise ignore this bullet. The rest of this adapter then applies with the printed URL standing in for the Artifact URL. Write the same five-section document as one self-contained, phone-friendly HTML file (viewport meta, inline CSS and JS) at the scratch path, load `artifact-design` only if your session lists it, and run `ateam page publish <file> --title "<title>"`. Stdout is the page URL. The page is served in a sandbox with no network: no `fetch` or XHR, no forms, no `localStorage`. Scripts and libraries from public CDNs load. Republish with `ateam page publish <file> --url <epic-recorded URL>`; never mint a second page for the same plan. Persist the URL with `bd note <EPIC_ID> "plan: <url>"` and report it to the DRI exactly as above. Any signed-in Dispatcher user can open the page.
